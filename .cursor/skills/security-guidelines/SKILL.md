# Безопасность

Чеклист для `security-auditor`. Короткие запреты этого репозитория — в
правиле `security`; здесь — как искать и как формулировать находку.

Каждая находка: файл и строка, сценарий, последствие, способ починки.
Гипотеза без строки кода помечается «требует проверки», не уязвимостью.

## Разбор пакетов

Главный вектор настольного клиента, который слушает сеть.

- Длина, счётчик элементов, версия схемы — из пакета. До выделения памяти
  проверяется верхняя граница.
- Битый кадр отбрасывается и идёт в статистику потерь, процесс не падает.
- Знаковые/беззнаковые длины, чтение за концом буфера, доверие UDP без
  проверки целостности — типичные дыры.

## Секреты и роли

- Пароли и ключи не живут в исходниках, тестах, логах, `*.ini` в git.
- Пароль хранится как хэш с солью, сравнение — не через `==` по строке.
- Права проверяются в сервисе доступа, не только скрытием кнопки.
- Действия, меняющие изделие, пишутся в журнал: кто, когда, что, результат.
  Журнал нельзя молча обрезать или подменить из интерфейса.

## Данные на диске

- Путь, собранный из внешнего ввода, не выходит из разрешённого каталога.
- SQL — только с привязкой параметров, не склейкой строк.
- В лог не попадают пароли и полные дампы с координатами.

## Что не писать в отчёт

Общие советы «используйте TLS» и «обновите зависимости» без привязки к
конкретному файлу этого дерева. Если канал по контракту открытый — это
ограничение изделия, не находка аудита, пока его не просили закрыть.
