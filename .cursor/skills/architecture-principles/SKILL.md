# Принципы архитектуры

Скилл для `senior-reviewer` и оркестратора. Правил здесь нет — только как
судить устройство системы. Конкретные слои этого репозитория — в
`project-context` и в промпте `senior-reviewer`.

## Направление зависимостей

Верх знает о низе, низ о верхе — нет.

```
интерфейс → модель состояния → приём потоков → сеанс управления → протокол
```

Признак нарушения: виджет открывает сокет, библиотека протокола тянет Qt Widgets,
два класса независимо хранят «текущую частоту».

## Единственность владения

На каждый внешний ресурс — один хозяин: один TCP-сеанс, один разбор кадра,
один источник правды для индикатора связи. Дублирование состояния между
хабом потоков и страницей интерфейса — дефект, а не удобство.

## Живучесть

Обрыв, мусор в пакете, отсутствие платы — штатные состояния, не аварии
процесса. Демо-режим не подменяет живые данные молча: оператор должен видеть,
что смотрит на модель, а не на изделие.

## Как предлагать правки

- Последовательность шагов, каждый оставляет сборку зелёной.
- Не «переписать слой», а «вынести ответственность X из класса Y в Z».
- Паттерн оправдан только снижением конкретной боли, не «так принято».
- Отличай долг (мешает менять код) от вкуса (можно спорить бесконечно).
