# Ведение задач

Два уровня, чтобы не смешивать черновое и итоговое:

- `.cursor/workspace/` — состояние текущей работы. Не коммитится, можно
  удалять целиком.
- `docs/plans/` и `docs/reports/` — планы и итоговые отчёты. Коммитятся.

## Файл состояния

Путь: `.cursor/workspace/YYYY-MM-DD-<краткое-имя>.md`.

```markdown
# <Задача>

Начато: 2026-09-21 09:40
План: docs/plans/2026-09-21-<имя>.md

## Задачи

| ID | Что | Файлы | Статус | Примечание |
|----|-----|-------|--------|------------|
| PROTO-001 | Разбор кадра триангуляции | protocol/pf60_protocol.cpp | ✅ | тест protocol зелёный |
| UI-002 | Показ триангуляции на карте | src/map/items/TriangulationItem.cpp | 🔄 | |
| DOC-003 | Обновить контракт | protocol/documentation/current_protocol.md | ⏳ | |

## Журнал
- 09:42 PROTO-001: worker внёс правку, test-runner 5/5 зелёных
- 09:55 PROTO-001: reviewer без критичных замечаний, закрыто
- 09:58 UI-002: worker начал

## Открытые вопросы
- <то, что требует ответа пользователя>
```

Статусы: `⏳` не начато, `🔄` в работе, `✅` готово, `⛔` заблокировано,
`❌` отменено.

## Правила

- Файл состояния создаётся один раз в начале и обновляется после каждого
  закрытого шага. Обновление статуса — часть шага, а не «потом».
- В журнал попадает результат, а не намерение: «тесты 5/5 зелёных», а не
  «запускаю тесты».
- `⛔` обязательно сопровождается причиной в примечании. Заблокированную задачу
  нельзя молча пропустить — о ней сообщают пользователю.
- Если пользователь дал свой файл задач (например `TODO.md`), работай в нём и
  отмечай статусы там же, а в `.cursor/workspace/` держи только ссылку на него.
- Закончив работу целиком, перенеси итог в `docs/reports/` и оставь файл
  состояния как есть — он одноразовый.
