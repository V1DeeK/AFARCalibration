# Git в этом репозитории

## Сообщение коммита

Формат: `тип(scope): тема`. Тема на русском, повелительное наклонение, до
72 символов, без точки в конце.

Типы: `feat`, `fix`, `refactor`, `test`, `docs`, `build`, `perf`, `chore`.

Scope: `protocol`, `connection`, `streams`, `ui`, `map`, `auth`, `record`,
`video`, `build`, `docs`, `tests`.

Примеры:

```
feat(streams): считать потери пакетов по каждому каналу отдельно
fix(connection): не терять резервный адрес после обрыва CONTROL
refactor(ui): вынести сборку панели потоков из MainWindow
test(protocol): покрыть обрезанный кадр спектра
```

Тело добавляй только если решение неочевидно: что было не так и почему выбран
такой путь. Пересказывать diff не нужно — он и так в коммите.

## Как собрать сообщение

1. `git diff --staged` — если индекс пуст, `git diff`.
2. Определи, что это по сути: новое поведение, исправление, перестановка кода
   без смены поведения, тест, документация.
3. Scope — по каталогу, который затронут сильнее всего. Затронуто несколько
   слоёв равномерно — это признак, что коммит стоит разбить.

## Безопасные и небезопасные операции

Делаю без спроса: `git status`, `git diff`, `git log`, `git show`,
`git add <конкретные файлы>`.

Только по явной просьбе: `git commit`, `git push`, `git checkout`,
`git switch`, `git reset`, `git rebase`, `git stash`, `git clean`,
`git branch -d`.

Никогда: `git push --force` в общую ветку, `git reset --hard` с
незакоммиченными изменениями пользователя, `git clean -fdx`.

## Чего не должно попасть в коммит

`build/`, `*.exe`, `*.dll`, `*.a`, `*.o`, `*.log`, `.cursor/workspace/`,
`maps/*.mbtiles`, реальные адреса стендов и пароли в `station.ini`.

Перед коммитом проверь `git status`: если в индексе есть что-то из этого
списка — сначала скажи об этом, потом действуй.
