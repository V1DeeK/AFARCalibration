# /orchestrate — крупная задача

Оркестратор — это ты, основной агент. Субагенты выполняют шаги и возвращают
отчёты. Ты решаешь, что делать дальше, и держишь общую картину. Субагенты
между собой не общаются и не помнят переписку: весь нужный контекст ты
передаёшь в задании каждому.

## Фаза 1. План

Запусти `planner`. Получишь список задач вида `PROTO-001` с файлами, критерием
готовности и зависимостями.

Покажи план пользователю и дождись подтверждения, прежде чем писать код.
Если в плане есть раздел «Требует уточнения» — задай эти вопросы сейчас, а не
на середине работы.

Заведи файл состояния `.cursor/workspace/<дата>-<задача>.md` по шаблону из
скилла `task-management` и отмечай в нём прогресс.

## Фаза 2. Выполнение

Для каждой задачи плана по очереди:

```
worker → test-runner → [debugger, если упало] → reviewer → [worker, если критично]
```

- `worker` реализует задачу. В задании: номер задачи, файлы, что сделать,
  критерий готовности.
- `test-runner` собирает и гоняет `ctest`.
- Если тесты упали и `test-runner` не починил — `debugger` с его отчётом.
  Максимум два круга. Дальше — остановка и разговор с пользователем.
- `reviewer` смотрит диф. Критичные замечания возвращаются в `worker`,
  затем тесты прогоняются заново.
- Обнови статус задачи в файле состояния и одной строкой сообщи пользователю,
  что закрыто.

Порядок задач берётся из зависимостей плана. Параллельно запускать субагентов
можно только если они правят разные файлы — иначе они затрут правки друг друга.

## Фаза 3. Завершение

1. Полный прогон: `ctest --test-dir build --output-on-failure`.
2. `senior-reviewer`, если работа затронула границы слоёв или добавила модуль.
3. `security-auditor`, если работа затронула `protocol/`, `connection/`,
   `streams/` или `auth/`.
4. `documenter` — обновить контракт, описание протокола, README и отчёт
   в `docs/reports/`.

## Правила остановки

Останавливайся и спрашивай пользователя, если:

- план требует изменить контракт `protocol/documentation/current_protocol.md`;
- два круга починки не дали зелёных тестов;
- задача требует трогать тулчейн, версию Qt или `build/`;
- `senior-reviewer` говорит, что задача упирается в архитектуру.

Молча обходить эти случаи нельзя.
