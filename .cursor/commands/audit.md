# /audit — состояние проекта

Полный разбор всего проекта, а не отдельного дифа. Занимает время и токены:
не запускай его вместо `/review-changes`.

## Шаги

Шаги 1–3 независимы и правок не вносят — запускай все три субагента
параллельно, одним сообщением с тремя вызовами.

```
- [ ] 1. Архитектура — субагент senior-reviewer
- [ ] 2. Безопасность — субагент security-auditor
- [ ] 3. Качество и покрытие — субагент reviewer
- [ ] 4. Фактическое состояние сборки и тестов — субагент test-runner
- [ ] 5. Сводный отчёт — субагент documenter
- [ ] 6. Исправления — только с подтверждения пользователя
```

**1. Архитектура.** Границы слоёв `ui → model → streams → connection →
protocol`, разрастание `MainWindow` и `StreamHub`, дублирование состояния,
поведение при обрыве связи и при отсутствии платы. Опора — скилл
`architecture-principles`.

**2. Безопасность.** Разбор недоверенных пакетов, `auth/`, журнал аудита,
секреты в репозитории, SQL в `record/` и `map/MBTilesSource`. Опора —
скилл `security-guidelines`.

**3. Качество и покрытие.** Дублирование, мёртвый код, магические числа,
проглоченные ошибки. Отдельно — какие модули вообще не покрыты тестами:
сверь содержимое `src/` со списком тестов `geo`, `mbtiles`, `recording`,
`hotkeys`, `protocol`.

**4. Факты.** `test-runner` показывает реальное положение дел: собирается ли
проект, сколько тестов и сколько зелёных. Без этого оценка — гадание.

**5. Отчёт.** `documenter` собирает всё в `docs/reports/YYYY-MM-DD-audit.md`.

## Формат сводки

```
## Состояние
Сборка: ок / сломана        Тесты: N/M зелёных
Непокрытые модули: <список>

## Находки по приоритету
1. [критично] <что> — <где> — <почему это важно>
2. [высокий]  ...

## Оценка
Архитектура N/10 · Безопасность N/10 · Качество N/10 · Тесты N/10

## Что делать в первую очередь
1. <шаг, который снимает наибольший риск>
```

Оценка обосновывается находками. Цифра без объяснения бесполезна.

**6.** Покажи сводку и спроси, что исправлять. Ничего не чини по итогам аудита
без подтверждения — аудит и правка это разные решения.
