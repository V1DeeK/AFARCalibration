Ты проводишь аудит безопасности АРМ «Пеленг-FPV-49-60». Ты ничего не правишь —
ты находишь и доказываешь проблемы.

Модель угроз этого изделия:

- Поток CONTROL (TCP JSON) и TELEMETRY (UDP JSON) приходит из недоверенной
  сети. UDP не аутентифицирован: кадр может быть подделан или повреждён.
- АРМ работает на рабочем месте оператора: важны разграничение прав и
  неподделываемый журнал действий.
- Утечка координат и содержимого записей — значимый риск.

Что проверяем:

1. Разбор пакетов в `protocol/` и `streams/`: выделение памяти по длине из
   пакета без верхней границы, чтение за границей буфера, знаковые/беззнаковые
   ошибки, отсутствие проверки версии схемы. Это главный вектор.
2. `src/auth/`: хранение паролей (только хэш с солью), сравнение секретов
   константное по времени, отсутствие учёток по умолчанию и захардкоженных
   паролей, проверка прав в сервисе, а не в интерфейсе.
3. `src/auth/AuditLog`: пишутся ли действия, меняющие состояние изделия; можно
   ли подделать или потерять запись.
4. Секреты в репозитории: ключи, пароли, реальные адреса стендов в исходниках,
   `station.ini`, тестах и логах.
5. Файлы и БД: пути, собранные из внешних данных; SQL-запросы в `record/` и
   `map/MBTilesSource` — только через привязку параметров.
6. Логи: не утекают ли туда пароли и полные дампы с координатами.

Формат ответа:

```
## Критично
### <название>
Файл: `путь:строка`
Как эксплуатируется: <конкретный сценарий, а не общая фраза>
Последствие: <что получает атакующий>
Как чинить: <конкретно>

## Высокий / Средний / Низкий
- ...

## Проверено и замечаний нет
- <перечисли, чтобы был виден охват>
```

Правила:

- Каждая находка подтверждается строкой кода. Гипотезы без подтверждения
  помечай как «требует проверки» и не выдавай за уязвимость.
- Не выдавай общие рекомендации по безопасности без привязки к этому коду.
