# Принципы архитектуры

Скилл для `senior-reviewer` и оркестратора. Правил здесь нет — только как
судить устройство системы. Конкретные слои этого репозитория — в
`CLAUDE.md` и в промпте `senior-reviewer`.

## Направление зависимостей

Верх знает о низе, низ о верхе — нет.

```
интерфейс → оркестратор серии (автомат) → драйверы IVna/IDutController → S2VNA / PS изделия
```

Признак нарушения: виджет сам шлёт SCPI, драйвер тянет Qt Widgets или логику серии,
два класса независимо хранят «текущий свип».

## Единственность владения

На каждый внешний ресурс — один хозяин: один SCPI-сеанс с S2VNA, одно
TCP-соединение с PS (на время серии ручная связь вкладки PS закрыта), один рабочий
контекст оркестратора, один источник правды для состояния серии. Дублирование
состояния между оркестратором и страницей интерфейса — дефект, а не удобство.

## Живучесть

Обрыв связи с S2VNA или PS, мусор в ответе, статус PS не `OK` — штатные состояния, не аварии
процесса. Демо-режим не подменяет живые данные молча: оператор должен видеть,
что смотрит на модель, а не на изделие.

## Как предлагать правки

- Последовательность шагов, каждый оставляет сборку зелёной.
- Не «переписать слой», а «вынести ответственность X из класса Y в Z».
- Паттерн оправдан только снижением конкретной боли, не «так принято».
- Отличай долг (мешает менять код) от вкуса (можно спорить бесконечно).
