# Документация проекта

## Карта документов

| Документ | Что в нём | Когда правится |
|----------|-----------|----------------|
| `afar_stage1_software_tz.pdf` | нормативное ТЗ этапа 1 | не правится, только сверяемся |
| `docs/contracts/vna-c2220-scpi.md` | закрытый набор SCPI, тайм-ауты, ошибки | до правки `src/vna/` |
| `docs/contracts/cpp-interfaces.md` | `IVna`, `IDutController`, автомат т. 8.4 | до правки `include/afar/`, `src/measure/` |
| `docs/contracts/data-formats.md` | каталог серии, AFARH5, AFARPQ, CSV, манифест | до правки `src/data/`, `src/report/` |
| `docs/contracts/attenuator-codes.md` | CSV кодов аттенюатора | до правки разбора кодов |
| `docs/operator-guide.md`, `docs/admin-guide.md` | работа оператора, развёртывание | при изменении GUI или поставки |
| `docs/plans/2026-10-03-plan-7-etapov.txt` | рабочий план и архитектурные запреты | читать перед правкой измерительного тракта |
| `README.md` | назначение, сборка, структура каталогов | при изменении сборки, зависимостей, раскладки |
| `docs/plans/` | планы работ от `planner` | при запуске `/orchestrate` |
| `docs/reports/` | итоговые отчёты и аудиты | по завершении работы |

Имя файла в `docs/`: `YYYY-MM-DD-краткое-имя.md`.

## Порядок при изменении обмена или формата

Только в такой последовательности, иначе код и контракт расходятся:

1. Контракт в `docs/contracts/` — описать команду, поле или файл.
2. Код (`src/vna/`, `include/afar/`, `src/data/`, `src/report/`) — реализовать.
3. Тест (`tests/test_c2220_driver.cpp`, `test_hdf5_store.cpp`,
   `test_export_manifest.cpp` …) — корректный, битый и граничный случай.
4. Руководства оператора/администратора — если меняется работа на стенде.
5. `README.md` — если изменились сборка, тесты или раскладка.

## Правила

- Русский язык. Пишем для инженера, который вернётся через полгода.
- Ссылаемся на файлы и функции, код не копируем: копия протухает молча.
- Неверная документация вреднее отсутствующей. Нашёл расхождение с кодом —
  чини его первым, даже если это не входило в задачу.
- Правка на одну строку в README не требует отдельного отчёта в `docs/`.
- Не описываем очевидное и не пересказываем diff.

## Шаблон отчёта
