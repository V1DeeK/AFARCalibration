# Стиль C++20 / Qt6

- C++20 без расширений компилятора. На MinGW действует
  `-Wall -Wextra -Wpedantic -Werror`: предупреждение = сломанная сборка.
- Класс = пара `.h/.cpp` в каталоге своего слоя. Новый файл обязательно
  добавляется в `src/CMakeLists.txt` в нужную библиотеку `afar_*`, иначе он
  не собирается.
- Слои `vna/`, `dut/`, `measure/`, `data/`, `cal/`, `qc/`, `sim/`, `core/` —
  без Qt Widgets (стандартная библиотека; `report/` использует только Qt Gui).
  Qt Widgets — только `ui/` и `app/`.
- Имена в `include/afar/` и контрактах (`f_start_hz`, `measure_s21`,
  `set_safe_state`) — snake_case по т. 8.3 ТЗ, посимвольно. Не переименовывать.
- Исключения драйверов переводятся в типизированные ошибки уровня
  приложения. `abort()` и `set_safe_state()` — `noexcept`. В деструкторах — без
  блокирующих аппаратных операций.
- У `QObject`-наследников — `Q_OBJECT`, родитель в конструкторе, владение через
  дерево объектов. `new` без родителя и без `std::unique_ptr` не используем.
- Связи — только новый синтаксис `connect(sender, &Type::sig, this, &Type::slot)`.
  Строковый SIGNAL/SLOT запрещён.
- Никакой блокирующей работы в GUI-потоке: SCPI, файлы серии, расчёт LUT —
  в рабочем потоке (`MeasureWorker`), результат в GUI — сигналом.
- Ошибки не глотаем. Либо возврат статуса/исключение вызывающему, либо запись
  в журнал серии с контекстом (канал, коды, частота, команда SCPI).

```cpp
// ❌ плохо — GUI сам говорит с прибором
transport.write("TRIG:SING");

// ✅ хорошо — через оркестратор в рабочем потоке
emit startRequested(config);
```

- Слои не перепрыгиваем: `ui/` не вызывает `IVna`/`IDutController` в обход
  `MeasurementOrchestrator` (одиночные S-параметры — через `MeasureWorker`).
- Числа в файлах (CSV, `.s2p`, JSON) пишутся независимо от локали: точка как
  десятичный разделитель.
- Комментарии — на русском и только там, где код не объясняет себя сам
  (пункт ТЗ, особенность S2VNA, обход бага тулчейна).
