# Документация

- Язык — русский. Пишем для инженера, который вернётся к коду через полгода.
- Нормативный источник — ТЗ `afar_stage1_software_tz.pdf`. Канон для кода —
  контракты `docs/contracts/`: `vna-c2220-scpi.md` (SCPI), `ps-json-protocol.md` (PS),
  `cpp-interfaces.md` (интерфейсы и автомат), `data-formats.md` (каталог
  серии, AFARH5, AFARPQ), `attenuator-codes.md`.
- Изменение обмена, интерфейса или формата → сначала правим контракт, потом
  код и тесты.
- Изменение способа сборки, зависимостей, списка тестов или структуры
  каталогов → правим `README.md` (и `CLAUDE.md`, если затронута раскладка).
- Изменение работы оператора → `docs/operator-guide.md`; развёртывания →
  `docs/admin-guide.md`.
- Планы, отчёты и разборы агентов складываем в `docs/` согласно
  `.claude/config.json`. Имя файла: `YYYY-MM-DD-краткое-имя.md`.
- Не плодим документы ради документов: если правка укладывается в одну строку
  README, отдельный отчёт не нужен.
- В документации ссылаемся на файлы и функции, а не копируем код — копия
  протухает.
