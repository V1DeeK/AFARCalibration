# Git

Коммиты — по правилу `commit-messages` и скиллу `git-helper`. Здесь — границы
действий, а не формат сообщения.

## Без спроса

`git status`, `git diff`, `git log`, `git show`. Подготовка индекса —
`git add` конкретных файлов задачи, не `git add -A`.

## Только по явной просьбе

`git commit`, `git push`, смена ветки, `git stash`, `git rebase`, `git reset`,
`git clean`, удаление веток.

## Никогда

- Прямой push в `main`, кроме мелких правок документации по согласованию
  (`docs/CONTRIBUTING.md`): фичи и исправления — ветка `feat/…`/`fix/…` и PR.
- `git push --force` в общую ветку (`main` / `master`).
- `git reset --hard` при незакоммиченных правках пользователя.
- `git clean -fdx`.
- Обход хуков (`--no-verify`), если об этом не просили отдельно.

## Индекс

В коммит не кладём `build/`, `dist/`, `*.exe`, `*.dll`, `*.log`,
`.claude/workspace/`, каталоги серий с измерениями, пароли и боевые IP стенда.
Увидел такое в индексе — сначала скажи, потом действуй.
