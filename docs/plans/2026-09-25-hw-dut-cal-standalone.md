## Факт: S2VNA обязателен или COM напрямую?

Опора **только** на репозиторий (ТЗ, контракт, `S2VNA-setup`, UI/драйвер). Вывод для планирования:

| Источник | Явный факт |
|----------|------------|
| ТЗ (`build/tz_extract.txt`) | «ПЛАНАР C2220 **под управлением S2VNA**»; обязательное оборудование: C2220 + **установленное совместимое ПО S2VNA**; SCPI по Socket (основной) / COM (Windows-адаптер); команды — по руководству **установленной** S2VNA. |
| `docs/contracts/vna-c2220-scpi.md` | Контракт «C2220 / S2VNA»; транспорт Socket к профилю порта S2VNA (пример 5025); COM — тот же закрытый SCPI, отдельный класс; источники — РЭ **S2VNA**. |
| `docs/S2VNA-setup.md` | Порядок: установить S2VNA → запустить → связь с прибором → **включить Socket Server** → AFAR «S2VNA Socket/COM» → `*IDN?`. |
| `ConnectionBar` | Режимы: «Имитатор» / **«S2VNA Socket»** / **«S2VNA COM»** — не «C2220 USB/COM напрямую». |
| `C2220Vna` | SCPI поверх `IScpiTransport`; не содержит логики «драйвер Planar USB без S2VNA». |

**В репозитории нет факта**, что прошивка C2220 принимает SCPI по COM/USB **без** запущенной S2VNA (как SCPI-сервера / remote control). Есть факт, что Socket Server включается **в S2VNA**, а COM в UI назван «S2VNA COM».

**Следствие:** цель пользователя «программа сама … без S2VNA» **противоречит формулировкам ТЗ §3.1 и текущей архитектуре**. Реализация «без процесса S2VNA» = либо (а) уточнение заказчика + иной транспорт/драйвер вне текущего контракта, либо (б) интерпретация «без ручной калибровки в UI S2VNA» при **всё ещё работающем** SCPI-сервере S2VNA. Без ответа — в «Требует уточнения»; волна B не должна обещать удаление S2VNA из стека.

## Риски / блокеры

- **Блокер C:** нет протокола контроллера (т. 14) → HW-DUT-01…04 «полностью» невозможны; любой выдуманный кадр — дефект.
- **Конфликт политики:** ТЗ и репозиторий предполагают S2VNA; цель «без S2VNA» не подтверждена фактами транспорта → риск сорвать приёмку по §3.1.
- **SCPI вне контракта:** уже существующий `calibrate_two_port` с `SENS:CORR:COLL:*` — риск регрессии/брака ревью; волна B обязана выровнять контракт↔код **до** расширения UI.
- **`averages` / overload:** поля есть, SCPI усреднения и overload в контракте нет (§7) — не выдумывать в B.
- **Полный AT-04:** сотни МБ и долгое время — нельзя включать в обычный `ctest`; GUI должен предупреждать.
- **Метролог:** без формы утверждения FR-05/AT-13 формально не закрыть (т. 12.3).
- **README / tz-status vs код:** SOLT-UI и «Измерить…» описаны шире, чем `MeasureTab`; README пишет, что COM «скрыт», а `ConnectionBar` всё ещё показывает «S2VNA COM» — выровнять в волне A/B.
