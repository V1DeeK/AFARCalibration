# План: AFAR RX Calibration Studio, этап 1

Документ: AFAR-RX-CAL-SW-TZ-01, ред. 1.0 от 29.08.2026.
Продукт: настольная программа характеризации 16 приёмных каналов АФАР на ПЛАНАР C2220 под S2VNA.
Репозиторий зелёный: нет `CMakeLists.txt`, `src/`, `tests/`. Код приложения этим планом не пишется.

Не входит в приёмку v1.0 и не планируется здесь: сканер ближнего поля, кодирование Хадамарда, диаграммы лучей, моноимпульс. Для них — стабильные форматы и интерфейсы расширения (см. DOC-003, DOC-004).

Не делать в волнах 0–9: установщик, SBOM, 24-часовой прогон AT-12, смена тулчейна, правки `build/`. Сначала скелет, контракты, имитаторы, матядро, GUI, затем драйвер C2220.

## Цель

Собрать проверяемый каркас AFAR RX Calibration Studio на Windows 10/11 x64 (C++20, CMake/CTest, Qt 6, HDF5, Parquet), в котором GUI не управляет железом, аппаратура сериализуется в `measurement-core`, форматы серии и интерфейсы `IVna` / `IDutController` совпадают с т. 8.3 ТЗ, а приёмка AT-01…AT-11 закрывается на имитаторах; реальное изделие — заглушка до передачи протокола.

## Критерий готовности

- `cmake -S . -B build` и `cmake --build build` на Windows x64 проходят без смены тулчейна и без записи в `build/` из исходников.
- `ctest --test-dir build --output-on-failure` закрывает AT-02, AT-03, AT-05…AT-11 на имитаторах; AT-01 — на имитаторе `*IDN?` и на живом C2220, когда прибор доступен.
- Каталог серии содержит `run-config.json`, `attenuator-codes.csv`, `raw-s21.h5`, `direct-lut.parquet`, `inverse-lut.parquet`, `run-events.jsonl`, `report.pdf`, `manifest.sha256`; повторное открытие и SHA-256 совпадают (AT-11).
- Интерфейсы `IVna` / `IDutController` не упрощены относительно т. 8.3; драйвер C2220 использует только команды из контракта `docs/contracts/vna-c2220-scpi.md` (раздел 15 ТЗ).
- Без протокола контроллера программа не подключается к реальному DUT: только GUI + ядро + имитаторы + заглушка `IDutController`.
- AT-04 (полная серия 65 536 состояний) — отдельная волна после AT-03; AT-12, установщик, SBOM, AT-13, AT-14 — после волн 0–9 и данных заказчика (т. 14).

### DOC-002 — Контракт драйвера C2220 / S2VNA (раздел 15)

Файлы: `docs/contracts/vna-c2220-scpi.md`
Что сделать: зафиксировать транспорт и команды **только** из источников ниже, без выдуманных SCPI. Сверка синтаксиса с фактически установленной версией S2VNA — явный шаг перед рабочим кодом драйвера (волна 9), не часть волны 0.

Источники (ТЗ р. 15), обязательные ссылки в контракте:

1. Официальная страница C2220: https://planarchel.ru/catalog/analizatory_tsepey_vektornye/vektornye_analizatory_tsepey_kobalt/analizator-tsepey-vektornyy-c2220/ — диапазон 0,1 МГц–20 ГГц, 2 порта, S11/S21/S12/S22, динамика 145 дБ тип. (маркетинг страницы; в ТС таблица 1.2 для C2220: ТХ 135 дБ, 1 МГц–20 ГГц, ПЧ 10 Гц — в ПО не проверять «145» как допуск), мощность −60…+10 дБм, до 500 001 точек, COM и TCP/IP Socket. Прямой доступ к приёмникам есть на приборе; HW-VNA-05: программа **не** включает его сама.
2. Руководство по программированию S2VNA: https://planarchel.ru/instruction/s2vna/ и локальные PDF в `Planar_documentation/` (ТС Cxx20 `TS_RU_Схх20_03.07.2026.pdf`; РЭ Cobalt ч. 1; РЭ S2VNA ч. 2 версия 26.3 от 24.06.2026, 2622 стр., «Руководство по программированию» с стр. 1103).
3. Copper Mountain S2VNA and S4VNA SCPI Programming Manual: https://coppermountaintech.com/wp-content/uploads/2020/09/SxVNA-SCPI-Programming-Manual-2.pdf и Operating+Programming 24.1.5: https://coppermountaintech.com/wp-content/uploads/2026/04/S2VNA-Operating-and-Programming-Manual.pdf
4. Прямой доступ: https://planarchel.ru/instruction/s2vna/systrecdiracc.html — `SYSTem:RECeiver:DIRect:ACCess[:STATe] {OFF|ON|0|1}`, только C2220, пресет 0 (OFF). Также https://planarchel.ru/instruction/s2vna/direct-receiver-access-c2.html

Локальный справочник команд (РЭ S2VNA ч. 2, оглавление): Socket vs HiSLIP стр. 1111; `*IDN?` 1158; `*OPC?` 1162; `CALC:DATA:SDAT` 1229; `CALC:DATA:XAX?` 1235; `CALC:PAR:DEF` 1479; `SENS:BAND` 1786; `SENS:FREQ:DATA?` 2088; `SENS:FREQ:STAR` 2094; `SENS:SWE:POIN` 2157; `SOUR:POW` 2192; `SYST:ERR?` 2359; `SYST:REC:DIR:ACC` 2405; `TRIG:SING` 2452. Рекомендации: «Программный запуск и ожидание сканирования».

Факты для контракта (не дополнять другими командами в v1 драйвера):

- Транспорт: TCP/IP Socket, порт по умолчанию **5025** (настраивается в S2VNA: System > Misc Setup > Network Remote Control Settings > Socket Server/Port). В `run-config.json` порт — поле профиля, не константа кода. COM — отдельный Windows-адаптер, не смешивать с Socket в одном классе.
- Идентификация: `*IDN?` (HW-VNA-01).
- Ожидание свипа: `TRIG:SING` + `*OPC?`.
- Ошибки: `SYST:ERR?` после группы команд (HW-VNA-03); в событии — исходная команда, код, текст; сырые данные не портить.
- Настройка: `SENS:FREQ:STAR` / `STOP`, `SENS:SWE:POIN`, `SENS:BAND`, `SOUR:POW`, `CALC:PAR:DEF S21` (HW-VNA-02).
- Чтение: `CALC:DATA:SDAT` и `CALC:DATA:XAX?` / `SENS:FREQ:DATA?`.
- Прямой доступ: `SYST:REC:DIR:ACC` — запрещён по умолчанию; при старте серии запросить состояние и **отклонить**, если ON без явного профиля стенда (HW-VNA-05).
- Тайм-ауты по умолчанию: соединение 3 с, свип 30 с, 2 повтора (HW-VNA-04).
- ТС Cxx20: мощность порта −60…+10 дБм; точек 2…500 001; ПЧ C2220 1 Гц…1 МГц. Программа проверяет попадание конфига в эти пределы прибора, не «гарантирует сохранность изделия» (т. 11).

Проверка: в контракте есть таблица команда → назначение → ссылка р. 15 / стр. локального РЭ; нет команд вне списка.
Зависит от: —

## Риски

- Версия S2VNA на стенде ≠ 26.3 локального РЭ: синтаксис `CALC:DATA:SDAT` / оси / `SYST:REC:DIR:ACC` может отличаться. Смотреть DOC-002 и фактический Help прибора до VNA-003.
- Маркетинговая динамика 145 дБ на сайте vs ТХ 135 дБ в `TS_RU_Схх20_03.07.2026.pdf` табл. 1.2 — не делать из этого порог ПО.
- HDF5 `complex128` непереносим — сразу compound `re`/`im` + атрибут схемы (т. 7.2).
- Полный HDF5 ~ 13,2e6 × 16 байт ≈ 200+ МБ плюс QC; диск и AT-04 по времени — основной риск волны 10.
- Arrow/Parquet на Windows (MSVC vs MinGW) — выбрать один генератор в README и не менять его «по дороге».
- Размерность `/raw/reference_s21` `[16,N_A+1,N_F]` двусмысленна; неверная интерпретация сломает опору и LUT.
- GUI, шлющий SCPI «для удобства отладки», нарушит ТЗ 8.2 — ревью слоёв после UI-004.
- Реальный DUT без протокола: любой «временный» бинарный кадр в `dut/` — дефект. Только stub + simulator.
- Режим прямого доступа, включённый руками в S2VNA, обязан стопорить серию; иначе метрология тракта не та (HW-VNA-05, т. 11 п. 5).
- Пороги FR-05/FR-17 без подписи метролога нельзя выдавать в отчёте как аттестованные.
- NFR-01 (10 мс между кодом и свипом) и рост памяти 24 ч — не закрываются волнами 0–9.

## Требует уточнения

Из т. 14 ТЗ (не выдумывать, без этого нет интеграции с изделием):

1. Электрическая схема подключения C2220 к одному каналу и к общему выходу.
2. Максимально допустимые уровни каналов и профиль `safe_state`.
3. Полная спецификация протокола контроллера АФАР (кадры, CRC, скорость, тайминги, ошибки) — до неё только GUI, ядро, имитаторы, `StubDutController`.
4. Утверждённая таблица кодов аттенюатора (пример CSV — не изделие).
5. Требования к 15 неактивным каналам при измерении одного (нагрузки 50 Ω — только текст мастера, без логики контроллера).
