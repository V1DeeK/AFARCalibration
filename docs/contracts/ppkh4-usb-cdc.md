# Плата ППКХ4: настройка одного канала по USB

Источник: репозиторий пользователя `V1DeeK/1Chanel` (прошивка
`firmware/src/main.c`, страница `web/index.html`, `README.md`, схема
`ППКХ4.pdf`). Вкладка «Измерение S-параметров» → «Настройка 1 канала»
повторяет эту страницу на Qt. Протокол задаёт прошивка 1Chanel; здесь —
только то, что использует программа. Новая команда — сначала в прошивку и
сюда, потом в код.

## Что это и чего это не касается

- Плата ППКХ4 на STM32F407 выдвигает кадр фазы и аттенюации в модуль на
  разъёме X2 (линии DATA/CLK/LE через буфер DD4). Канал X1 прошивка держит
  в безопасном состоянии.
- Это ручной стендовый инструмент для одного модуля: оператор ставит коды и
  смотрит результат на C2220. С серией измерений, `MeasurementOrchestrator`,
  `IDutController` и PS изделия вкладка не связана; C2220 сама не трогает.
- Обмен с решёткой 16 каналов по-прежнему идёт только через PS
  (`ps-ethernet-v8.md`); эта плата его не заменяет.

## Канал связи

- USB CDC, виртуальный COM-порт, VID `0483`, PID `5740`. Драйвер на
  Windows 10/11 и macOS не нужен. Скорость порта не важна, программа
  открывает 115200 8N1.
- Код: `src/ppkh4/Ppkh4Link` (Qt Serial Port). Без модуля Qt Serial Port
  программа собирается, вкладка показывает «нет модуля Qt Serial Port».
- Команда — строка ASCII, завершённая `\n`. Ответ — строка `OK …` или
  `ERR …`. Строки без `OK`/`ERR` (продолжение `HELP`) только пишутся в журнал.
- Команды идут по одной: следующая уходит после ответа или через 2 с
  (тайм-аут, как на исходной странице).

## Команды, которые шлёт программа

| Команда | Когда | Ответ |
|---|---|---|
| `PING` | сразу после открытия порта | `OK PONG`; иначе «плата не отвечает» и порт закрывается |
| `CFG LSBFIRST\|CLKIDLE\|LEACT\|LEMODE\|HALFUS\|LEUS <число>` | после `PING` и при любой правке формата | `OK CFG …` |
| `SEND <бит> <hex>` | после `CFG`, при каждой смене фазы/аттенюации (с задержкой 60 мс), на каждом шаге перебора | `OK SEND BITS=… HEX=…` |

`<бит>` — 1…256, `<hex>` — ровно ceil(бит/4) цифр, заглавные буквы, старшая
цифра первой. Остальные команды прошивки (`INFO`, `STATUS`, `PWR`, `STB`,
`STBP`, `HELP`) программа не шлёт.

Параметры линий (`CFG`): `LSBFIRST` 0 — старшим битом вперёд; `CLKIDLE`
0 — защёлка по фронту, 1 — по спаду; `LEACT` активный уровень LE; `LEMODE`
0 — импульс LE после данных, 1 — LE активен во время передачи; `HALFUS`
полупериод CLK и `LEUS` импульс LE, 1…10000 мкс.

## Кадр

Код: `src/ppkh4/Ppkh4Frame` (без Qt), тест `tests/test_ppkh4_frame.cpp`.

- По умолчанию 12 бит: биты 11…6 — аттенюация, 5…0 — фаза, по 6 бит.
- Фаза: код × 5.625° (360/64), код 0 = 0°.
- Аттенюация: шаг 0.5 дБ; код 0 (все нули) = −31.5 дБ, код 63 (все
  единицы) = 0 дБ. Ввод в дБ знак не учитывает: 10 и −10 дБ дают код 43.
- Раскладку можно поменять на вкладке («Формат кадра»): всего бит, младший
  бит и ширина каждого поля (до 16 бит), шаг, инверсия, обратный порядок бит
  поля, фиксированные биты (hex) вне полей. Неверная запись фиксированных
  бит даёт ноль. Перекрытие полей и выход за кадр подсвечиваются, кадр всё
  равно уходит (как на исходной странице).
- Настройки хранятся в настройках программы (`singleChannel/*`), вместо
  `localStorage` страницы.

## Перебор состояний

Фаза или аттенюация, коды «от»…«до» с шагом, пауза ≥ 50 мс (по умолчанию
1500 мс) между кадрами. Пауза отсчитывается после ответа на `SEND`. После
«до» перебор начинается снова с «от», пока оператор не нажмёт «Стоп» или
связь не пропадёт.
