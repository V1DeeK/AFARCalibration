# Обмен с изделием по Ethernet — протокол v8

Источник: `structural_scheme_v8.docx` (получен от пользователя 16.10.2026).
Этот контракт заменяет `ps-json-protocol.md` для текущей реализации.

## Каналы

- Управление: TCP 49600, по одному объекту JSON в строке, завершённой `\n`.
  Первая команда после соединения — `hello` с `ver`, `tlm_ip`, `tlm_port`.
- Техническое состояние: UDP на адрес и порт из `hello`, один пакет ровно
  10 байт раз в секунду. Это единственная UDP-телеметрия, не JSON. По
  уточнению пользователя бит 0 — младший бит байта 0, бит 8 — младший бит
  байта 1, и так далее. Биты 0–79 описаны таблицей 5 документа.
  У пакета нет номера, поэтому определить число потерянных пакетов нельзя.
  Полярность: почти все биты — 1 = исправно, но биты 13 (проверка канала
  данных), 14 (уровень входного сигнала) и 15 (приём данных в память) —
  флаги ошибок, у них 0 = исправно.
- IQ: `libiio` на TCP 30431, устройство `cf-ad9361-lpc`, четыре канала
  `voltage0`–`voltage3` (I1, Q1, I2, Q2), `le:S12/16>>0`. Только чтение и
  только в режиме `SERVICE`; параметры тракта через libiio не записывать.

## Команды управления

Обёртка JSON: `msg_type`, `msg_class`, `msg_count` 0–255, `payload`.
Ответ повторяет тип и счётчик команды. Статусы: `OK`, `BUSY`,
`NOT_SUPPORTED`, `INVALID_ARGUMENT`, `HW_NOT_READY`.

Режимы: `IDLE`, `FULL_SCAN_FREQ`, `OPERATIONAL`, `SERVICE`. Вход в
`SERVICE` из `IDLE/READY`. Режим узнаётся командой `get_state`, не из UDP.

Для калибровки в `SERVICE`:

- `set_rfm_params` / `get_rfm_params`: ровно 16 элементов `ch` с уникальными
  `n` от 1 до 16, `ph` и `att` от 0 до 63, `en` 0 или 1. Ответ содержит
  коды, считанные после записи.
- `get_rfm_telemetry`: `temp` — четыре температуры РЧ-модулей.
- `set_lo_params` / `get_lo_params`, `set_mixer_params` /
  `get_mixer_params`, `set_video_params` / `get_video_params` — управление
  внутренними модулями. Подробные поля и диапазоны: таблицы 28–33.
  Ответ и `set_*`, и `get_*` содержит установленные значения и телеметрию:
  `temp`, у гетеродинов и видеоприёмника ещё `lock`, у видеоприёмника `pres`
  (1 — уровень видеосигнала приемлемый). Отдельных команд
  «получение телеметрии гетеродина/смесителя/видеоприёмника», которые есть в
  оглавлении документа, в тексте нет: телеметрия приходит в этих ответах.
- `get_trx_status` и `get_pl_status` — состояние трансивера и ПЛИС.
- `set_beam_azimuth`, `set_beam`, `get_beam` — луч; `get_beam.src` принимает
  `AZIMUTH`, `TABLE`, `CODES`, `NONE`.
- `rs485_send` — передача HEX-строки; ответные байты PS возвращает в `data`,
  программа показывает их под полем ввода.
- `set_osd_text` (п. 3.6.1.11): `row` от 0 до 15 при PAL или до 12 при NTSC,
  `col` от 0 до 29, `text` — ASCII 0x20–0x7E, `col` + длина текста ≤ 30.
  Ответ повторяет параметры. Текст виден на экране при `src` = `TEXT`.
- `clear_osd_text` (п. 3.6.1.12): payload пустой, очищает весь экран OSD.

В любом режиме, состояние КА не меняется (п. 3.3.1):

- `set_osd`: один или несколько параметров таблицы 13 — `en` 0/1, `std`
  `PAL`/`NTSC`, `src` `AUTO`/`TEXT`, `fields` — массив из `state`, `freq`,
  `az`, `cls`, `snr` без повторов, `hos` и `vos` от −32 до +31. Не указанные
  параметры PS не меняет. Программа шлёт все параметры с формы.
- `get_osd`: payload пустой. Ответ `set_osd` и `get_osd` — все параметры
  таблицы 13 и `los` (0 — видеосигнал есть, 1 — нет).

Только в `IDLE`, состояние `READY` (п. 3.2); в `INIT`/`SELF_TEST` — `BUSY`,
в других режимах — `NOT_SUPPORTED`:

- `set_start_test`: payload пустой. Ответ приходит после самопроверки;
  результаты — в битах 72–79 UDP-пакета. Срок ответа в программе — 60 с
  (длительность самопроверки документ не задаёт).
- `set_reset`: payload пустой. PS отвечает, закрывает TCP и перезапускается
  (`INIT`); программа переподключается и снова шлёт `hello`. Кнопка
  перезапуска спрашивает подтверждение оператора.

Режим `OPERATIONAL` (`set_op_*`, `get_op_*`, события `send_op_*`) в этой
программе не реализуется: это работа АРМ РМО, калибровке он не нужен.

Команды `set_adc`, `get_adc`, `set_phase_atten`, `get_phase_atten`, `set_lo`,
`get_lo`, `set_mixer`, `get_mixer`, `set_video`, `get_video` не входят в v8.

Для `FULL_SCAN_FREQ`: `set_sff_parameters` принимает `freq_min`,
`freq_max` в пределах 4,9–6,0 ГГц, `az_min`, `az_max` в пределах ±30°.
Параметра `period` нет. Результат `send_sff_result` — событие с
`freq`, `cal` и массивом `fft`.

## Кнопки программы

Каждой команде, которую оператор шлёт сам, соответствует своя кнопка во
вкладке «Установка параметров» (кроме `rs485_send` — «Тестовый прогон»).
`hello` и `keep_alive` программа шлёт сама. Любую команду можно отправить и
вручную из «Одной команды».

| Команда | Где | Кнопка |
|---|---|---|
| `set_mode` | Режим изделия | «Перейти в сервисный», «Вернуть в ожидание» |
| `get_state` | Режим изделия | «Запросить состояние» |
| `set_start_test` | Режим изделия | «Запустить самопроверку» |
| `set_reset` | Режим изделия | «Перезапустить изделие…» (с подтверждением) |
| `set_beam_azimuth`, `set_beam`, `get_beam` | Луч | «Установить азимут», «Установить луч», «Запросить состояние луча» |
| `set_lo_params`, `get_lo_params` | Модули → гетеродины | «Записать», «Прочитать» |
| `set_mixer_params`, `get_mixer_params` | Модули → Смеситель | «Записать», «Прочитать» |
| `set_video_params`, `get_video_params` | Модули → Видеоприёмник | «Записать», «Прочитать» |
| `set_rfm_params`, `get_rfm_params` | Модули → Коды решётки | «Записать 16 каналов», «Прочитать из микросхем» |
| `get_trx_status` | Модули → Состояние | «Состояние трансивера» |
| `get_pl_status` | Модули → Состояние | «Состояние ПЛИС» |
| `get_rfm_telemetry` | Модули → Состояние | «Температуры РЧ-модулей» |
| `set_osd`, `get_osd` | Модули → OSD | «Записать OSD», «Прочитать OSD» |
| `set_osd_text`, `clear_osd_text` | Модули → OSD | «Вывести текст», «Очистить экран» |
| `set_sff_parameters`, `get_sff_parameters` | Полное сканирование | «Применить параметры», «Прочитать параметры» |
| `set_sff_start`, `set_sff_stop` | Полное сканирование | «Старт», «Стоп» |
| `rs485_send` | Тестовый прогон | отправка HEX-строки |

## Тесты

`tests/test_ps_v8_commands.cpp` (`ctest -R ps_v8_commands`): по одному
`TEST_CASE` на каждую команду и событие из п. 3.2–3.4 и 3.6 и отдельный на
UDP-пакет таблицы 5. Тест нажимает кнопку, как оператор, сверяет
`msg_type` и `payload`, принятые тестовым PS, с таблицами документа и
проверяет, что ответ показан на экране. Название кейса начинается с номера
пункта: `v8 3.6.1.5 set_lo_params …`.
