# Контракт форматов серии

Документ: AFAR-RX-CAL-SW-TZ-01, ред. 1.0 от 29.08.2026, пункты 6–7, DATA-01…DATA-03, LOG-01…LOG-03, FR-09.
Продукт: AFAR RX Calibration Studio, этап 1.
Задача: DOC-004.

Это контракт имён, полей, типов и размерностей. Реализация не упрощает набор файлов т. 7.1 и пути datasets т. 7.2. Поля, которых нет в ТЗ, не добавляются как обязательные.

## 1. Назначение

Серия измерений — каталог `RX16-YYYYMMDD-NNN/` с фиксированным составом файлов. Вход: `run-config.json` и `attenuator-codes.csv`. Выход: сырой HDF5, две LUT Parquet, журнал JSONL, PDF-протокол, манифест SHA-256.

Идентификатор серии по шаблону ТЗ: `RX16-` + дата `YYYYMMDD` + `-` + трёхзначный порядковый номер. Пример: `RX16-20260829-001`. Пользовательский идентификатор — только латиница, цифры, дефис и подчёркивание.

Кодировка текстовых файлов: UTF-8. Имена файлов — ASCII, дефис ASCII (`-`), не типографское тире из PDF.

## 2. Версионирование схем (DATA-02)

- Схемы версионируются именем, не молчаливым изменением полей.
- Несовместимое изменение требует **нового имени схемы**.
- Программа линейки **1.x обязана читать все ранее выпущенные схемы 1.x**.
- Имя схемы конфигурации этапа 1: `afar.stage1.run-config/v1`.
- Имена схем расширения этапа 2/3 (сканер, Хадамард, ДН, моноимпульс) резервируются отдельно и не входят в обязательный каталог v1.0.

Неизвестные поля в `run-config.json` — ошибка валидации до любого обращения к оборудованию (AT-02).

## 3. Каталог серии (т. 7.1)

Путь: `<корень данных>/<run_id>/`. Состав **обязателен и полон** — ни файла меньше, ни подмены канонических имён:

| Файл | Роль |
|------|------|
| `run-config.json` | применённая конфигурация серии (копия после старта неизменяема) |
| `attenuator-codes.csv` | таблица кодов аттенюатора |
| `raw-s21.h5` | канонические сырые многомерные данные |
| `direct-lut.parquet` | прямая LUT |
| `inverse-lut.parquet` | обратная LUT |
| `run-events.jsonl` | структурированный журнал событий |
| `report.pdf` | протокол серии |
| `manifest.sha256` | SHA-256 каждого файла каталога при закрытии |

Пути нормализуются. Выход за каталог серии запрещён (т. 10.4). Боевые адреса стенда в репозиторий не кладутся.

Обычные файлы пишутся во временное имя и атомарно переименовываются после проверки. Исключение: append-only `raw-s21.h5` и `run-events.jsonl` (т. 10.1).

## 4. Единицы и типы (DATA-01)

- Величина хранится **в единицах, указанных в имени поля** (`_hz`, `_dbm`, `_db`, `_deg`, `_ms`, `_c`, `_utc`).
- Частота — целое **uint64, герцы**, не ГГц и не float.
- Время — **UTC** с наносекундной либо микросекундной точностью.
- Фаза в исходных данных **не заменяет** комплексное число: сырьё — `re`/`im` (или `complex128`), не «фаза вместо S21».

## 5. `run-config.json` — схема `afar.stage1.run-config/v1` (т. 6.1)

Обязательный корень и вложенные блоки. Порт `5025` в примере ТЗ — параметр профиля, не константа программы.

### 5.1 Корень

| Поле | Тип | Смысл |
|------|-----|--------|
| `schema` | string | ровно `afar.stage1.run-config/v1` |

| `vna` | object | профиль ВАЦ |
| `controller` | object | профиль контроллера АФАР |
| `dut` | object | изделие и сетка кодов |
| `timing` | object | выдержки и опора |
| `limits` | object | пороги контроля качества |

| Поле | Тип | Смысл |
|------|-----|--------|
| `model` | string | модель прибора, для этапа 1 — ПЛАНАР C2220 |
| `host` | string | адрес Socket |
| `port` | integer | порт Socket из профиля S2VNA |
| `s_parameter` | string | для этапа 1 — `S21` |
| `f_start_hz` | integer (Гц) | начало полосы |
| `f_stop_hz` | integer (Гц) | конец полосы, строго больше старта |
| `points` | integer | число точек свипа `N_F` |
| `ifbw_hz` | integer (Гц) | полоса ПЧ |
| `power_dbm` | number (дБм) | мощность порта |
| `averages` | integer | усреднение |

### 5.3 Блок `controller`

| Поле | Тип | Смысл |
|------|-----|--------|
| `driver` | string | идентификатор драйвера |
| `endpoint` | string | точка подключения (COM, TCP и т.п.) |

### 5.4 Блок `dut`

| Поле | Тип | Смысл |
|------|-----|--------|
| `serial` | string | заводской номер изделия |
| `channels` | object | `{ "first", "last" }`, каналы 1…16 |
| `phase_codes` | object | `{ "first", "last", "lsb_deg" }`, коды 0…63 |
| `attenuator_codes_file` | string | имя CSV относительно каталога серии |
| `reference` | object | `{ "att_code", "phase_code" }` — опора по умолчанию 0 / 0 |

### 5.5 Блок `timing`

| Поле | Тип | Смысл |
|------|-----|--------|
| `settle_ms` | integer (мс) | выдержка по умолчанию |
| `reference_after_phase_row` | boolean | опора после каждой строки из 64 фаз |

### 5.6 Блок `limits`

| Поле | Тип | Смысл |
|------|-----|--------|
| `max_drift_phase_deg` | number (°) | порог дрейфа опоры |
| `max_phase_residual_deg` | number (°) | порог остатка фазы обратной LUT |

Стартовые пороги ТЗ (FR-17) — настройки ПО, не аттестованная метрология изделия. В обязательный JSON т. 6.1 входят только поля таблицы выше.

Машиночитаемая JSON Schema: `schemas/afar.stage1.run-config.v1.json`. Пример, валидный по схеме: `examples/run-config.example.json` (хост `127.0.0.1`, порт 5025 и `COM7` — иллюстрация профиля, не боевой стенд).

## 6. `attenuator-codes.csv` (т. 6.2)

Заголовок строго:

```
att_code,att_cmd_db,enabled,settle_ms
```

| Колонка | Смысл |
|---------|--------|
| `att_code` | код 0…63, уникален в файле |
| `att_cmd_db` | **номинальная подпись** и начальное приближение, не измерение |
| `enabled` | участвует ли код в переборе |
| `settle_ms` | выдержка этой строки (мс); может отличаться от `timing.settle_ms` |

Правила:

- Код **0 не означает физические 0 дБ**.
- Зависимость кода от децибел **не линейна** и не должна так интерпретироваться.
- `N_A` — число строк с `enabled=true`; ось `/axes/att_code` имеет длину `N_A`.

Пример CSV изделия — отдельная задача DATA-002. Пример ТЗ не является утверждённой таблицей заказчика (т. 14).

## 7. `raw-s21.h5` (т. 7.2)

Каноническое сырьё. Группы `/meta`, `/axes`, `/raw`, `/qc`.

Обозначения: `N_A` — число включённых кодов аттенюатора; `N_F` — `vna.points`; каналов 16; фазовых кодов 64.

### 7.1 Datasets

| Путь | Тип | Размерность |
|------|-----|-------------|
| `/meta/run_config_json` | UTF-8 | скаляр (текст применённого JSON) |
| `/meta/vna_idn` | UTF-8 | скаляр (ответ идентификации) |
| `/meta/vna_calibration_id` | UTF-8 | скаляр (идентификатор калибровки ВАЦ) |
| `/axes/channel` | uint8 | `[16]` |
| `/axes/att_code` | uint16 | `[N_A]` |
| `/axes/phase_code` | uint8 | `[64]` |
| `/axes/frequency_hz` | uint64 | `[N_F]` |
| `/raw/s21` | complex128 или compound | `[16, N_A, 64, N_F]` |
| `/raw/reference_s21` | complex128 или compound | `[16, N_A+1, N_F]` |
| `/raw/temperature_c` | float32 | `[16, N_A, 64]` |
| `/qc/overload` | bool | `[16, N_A, 64]` |
| `/qc/valid` | bool | `[16, N_A, 64, N_F]` |
| `/qc/attempt` | uint16 | `[16, N_A, 64]` |
| `/qc/completed` | bool | `[16, N_A, 64]` |

Порядок осей рабочих состояний: канал, код аттенюатора, код фазы, частота — как в размерности `/raw/s21`.

Запись состояния — транзакция: данные и флаги, затем `completed=true` (FR-07 п. 7). Частично записанный блок без `completed` при восстановлении не считается подтверждённым.

### 7.2 Комплексный тип

Если библиотека HDF5 даёт **переносимый** `complex128` — допускается он.

Иначе комплекс хранится как **compound** из двух `float64` с именами **`re`** и **`im`**.

Представление **обязано** быть зафиксировано в атрибуте схемы датасета (`/raw/s21` и `/raw/reference_s21`): либо факт native `complex128`, либо compound `re`/`im` float64. Читатель 1.x должен суметь открыть оба варианта семейства 1.x (DATA-02).

### 7.3 Размерность `/raw/reference_s21`

ТЗ задаёт **`[16, N_A+1, N_F]`**. Этот контракт повторяет размерность без изменения.

**Смысл оси `N_A+1` заказчиком не уточнён** (открытый вопрос плана, п. 13). Реализация не выдумывает семантику лишнего слота (глобальная опора, «до первой строки», фиктивный индекс и т.п.) до отдельного решения. Хранилище обязано создать датасет именно этой формы.

Опора по умолчанию: `att_code=0`, `phase_code=0` выбранного канала (FR-08). Частота опор задаётся `timing.reference_after_phase_row`.

### 7.4 Append-only и повтор (FR-09)

- Сырой HDF5 — **журнал только для добавления**: файл серии не пересоздаётся и не усекается в ходе измерения.
- Повтор измерения того же индекса **не удаляет** предыдущий факт и не сбрасывает `completed`.
- Повтор создаёт **новую попытку**: `/qc/attempt` увеличивается.
- Оси `attempt` у `/raw/s21` в т. 7.2 **нет**. Ячейка датасета держит актуальный свип; история попыток — в `/qc/attempt` и `run-events.jsonl` (и в табличном экспорте, где `attempt` — колонка). Пятая размерность HDF5 этим контрактом не вводится.

| Поле | Тип | Смысл |
|------|-----|--------|
| `run_id` | string | идентификатор серии |
| `timestamp_utc` | datetime64 (UTC) | время отсчёта |
| `channel` | uint8 | канал 1…16 |
| `att_code` | uint16 | фактически переданный код |
| `phase_code` | uint8 | код 0…63 |
| `freq_hz` | uint64 | частота, Гц |
| `s21_re` | float64 | действительная часть S21 |
| `s21_im` | float64 | мнимая часть S21 |
| `temp_c` | float32 | температура платы, °C |

Имя дополнительного CSV в ТЗ не задано; появление файла не подменяет `raw-s21.h5`.

## 9. LUT Parquet (т. 7.4)

Единицы — в имени колонки (DATA-01). Частота — `uint64` Гц.

### 9.1 `direct-lut.parquet`

Колонки в указанном порядке ТЗ:

`channel`, `freq_hz`, `att_code`, `phase_code`, `s21_re`, `s21_im`, `mag_db`, `phase_unwrapped_deg`, `atten_meas_db`, `phase_error_deg`, `drift_phase_deg`, `repeatability_db`, `repeatability_deg`, `valid`

Прямая LUT содержит фактически измеренные комплексы, модуль, развёрнутую фазу, оценку дрейфа, повторяемость и флаг пригодности для каждого канала, частоты и сочетания кодов (FR-13).

### 9.2 `inverse-lut.parquet`

`channel`, `freq_hz`, `target_atten_db`, `target_phase_deg`, `selected_att_code`, `selected_phase_code`, `measured_atten_db`, `measured_phase_deg`, `atten_residual_db`, `phase_residual_deg`, `valid`

Выбор кодов — по минимуму функционала ТЗ (формула 7), без гипотезы монотонности аттенюатора и линейности фазовращателя. Состояние `valid=false` не выбирается, если есть пригодное (FR-14, FR-15).

## 10. `run-events.jsonl` (т. 9, LOG-01…LOG-03)

Одна строка — один JSON-объект, запись только добавлением.

### 10.1 Обязательные поля (LOG-01)

| Поле | Смысл |
|------|--------|
| `timestamp_utc` | время UTC |
| `level` | уровень |
| `component` | компонент |
| `event_code` | код события |
| `run_id` | идентификатор серии |
| `channel` | канал (пусто, если событие не привязано к каналу) |
| `att_code`, `phase_code` | коды состояния (пусто, если неприменимо) |
| `attempt` | попытка |
| `text` | человекочитаемый текст |

Переходы автомата пишутся с причиной, пользователем и снимком состояния стенда (т. 8.4).

### 10.2 Запрет двоичных S21 (LOG-02)

Полный обмен SCPI — только инженерный профиль. **Двоичные массивы S21 в текстовый журнал и JSONL не записываются.** Допустимы: команда, размер ответа, время выполнения, контрольная сумма блока.

### 10.3 Секреты (LOG-03)

Секреты, сетевые пароли и персональные данные в журнал не попадают. Конфигурация стенда — технологические данные, доступ — правами ОС.

## 11. `report.pdf`

Протокол серии. В каждом протоколе фиксируются версия программы, хеш сборки, компилятор и версии библиотек (т. 10.3). Содержание макета GUI/отчёта не заменяет машинные файлы HDF5/Parquet/манифеста.

## 12. `manifest.sha256` и успех экспорта (DATA-03, FR-09)

При закрытии серии считается SHA-256 **каждого** файла каталога (кроме самого манифеста). Формат строки как у `sha256sum`: `<64 hex><два пробела><имя файла>`.

**Экспорт считается успешным только после:**

1. повторного открытия записанных файлов;
2. проверки размеров;
3. проверки контрольных сумм SHA-256;
4. совпадения числа пригодных состояний с отчётом.

Иначе статус экспорта — неуспех, даже если файлы уже лежат на диске (AT-11).

## 13. Что этим контрактом не закрывается

- Смысл оси `N_A+1` у `/raw/reference_s21`.
- Источник значения `/meta/vna_calibration_id` (файл S2VNA / ручной ввод / SCPI) — в ТЗ поле есть, команды чтения нет.
- Утверждённая заказчиком таблица аттенюатора и протокол контроллера (т. 14).
- Форматы этапа 2/3.

## 14. Реализация raw-s21.h5 без libhdf5

На этапе 1 файл `raw-s21.h5` пишется **собственным бинарным контейнером** (без зависимости от libhdf5). Имя файла сохраняется по т. 7.1; семантика осей и слотов соответствует разделу 7, представление на диске:

| Поле | Тип | Смысл |
|------|-----|--------|
| magic | 8 байт | `AFARH5` + байт `0x01` + `NUL` |
| version | uint32 | `1` |
| n_channel, n_att, n_phase, n_freq | uint32 | размерности осей |
| channels[] | uint8 | ось каналов |
| att_codes[] | uint16 | ось включённых кодов аттенюатора (`N_A`) |
| phase_codes[] | uint8 | ось фаз |
| frequency_hz[] | uint64 | ось частот, Гц |
| слоты состояний | см. ниже | порядок: channel × att × phase |
| reference_s21 | re/im float64 × n_freq + флаг | форма `[n_channel, n_att+1]` |

Слот состояния: `s21.re/im` float64[`n_freq`], `temperature_c` float32, `overload` bool, `valid` bool[`n_freq`], `attempt` uint16, `completed` bool.

Правила записи (FR-09 / AT-05): один слот на `(channel, att_code, phase_code)`; при `completed=false` слот можно переписать; при `completed=true` запись отклоняется. Файл не усекается в ходе серии. Класс реализации: `afar::RawS21Store` (`src/data/RawS21Store.*`).

## 15. Реализация parquet без Arrow

На этапе 1 файлы `direct-lut.parquet` и `inverse-lut.parquet` пишутся **без Apache Arrow**: columnar TSV UTF-8 с заголовком колонок т. 7.4 (раздел 9) и расширением `.parquet` для совместимости каталога серии (т. 7.1).

Представление на диске:

| Поле | Тип | Смысл |
|------|-----|--------|
| magic | 7 байт | `AFARPQ` + байт `0x01` |
| тело | UTF-8 | TSV: первая строка — имена колонок ТЗ через табуляцию; далее строки данных |

Колонки и порядок — как в §9.1 / §9.2. Reader/writer: `afar::report::ParquetExport` (`src/report/ParquetExport.*`). Успех экспорта по-прежнему только после reopen, размеров, SHA-256 и совпадения числа `valid` с протоколом (DATA-03, AT-11).
