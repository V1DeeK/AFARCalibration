# Программная методика испытаний без S2VNA/C2220

## Автоматический набор

```powershell
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build -j 4
ctest --test-dir build --output-on-failure
```

Набор проверяет конфигурацию, математику LUT, QC, симуляторы, хранилище, паузу и
восстановление, ошибки, экспорт, манифест, SCPI-драйвер на TCP-стабе и GUI.

## Полный AT‑04 на симуляторе

```powershell
$env:AFAR_RUN_AT04='1'
.\build\tests\test_full_sim_run.exe "[full]"
.\build\tests\test_lut_perf.exe "[full]"
```

Ожидается 65 536 состояний и 13 172 736 комплексных точек. Производительность LUT
фиксируется в выводе; окончательный NFR‑03 оценивается на согласованном эталонном ПК.

## AT‑12

```powershell
$env:AFAR_RUN_AT12='1'
.\build\tests\test_at12_soak.exe
```

Не закрывайте терминал 24 часа. Сохраните вывод и CSV телеметрии. Временные значения
можно задавать только для отладки, не для приёмочного протокола.

## Независимая проверка контрольной серии

```powershell
.\tools\verify-series.ps1 -SelfTest
.\tools\verify-series.ps1 "C:\Data\RX16-YYYYMMDD-NNN"
```

Зафиксируйте сводку `PASS`, число файлов, строк, пригодных LUT и событий.

## Что требует реального стенда

Идентификация и калибровка C2220, фактические четыре S‑параметра, тайминги,
перегрузка, safe-state АФАР, аварийные сценарии физического контроллера и
метрологические допуски выполняются отдельным протоколом после получения оборудования.
